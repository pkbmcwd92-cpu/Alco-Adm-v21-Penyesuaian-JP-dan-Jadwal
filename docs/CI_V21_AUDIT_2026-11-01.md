## Akar masalah dan koreksi

1. Tes navigasi masih mengasumsikan ATP langsung menuju Semester dan menganggap handler penyimpanan administrasi sebagai no-op. Tes kini menjalankan callback App yang sebenarnya, memeriksa elemen UI, dan menguji urutan **06 ATP → 07 Pemetaan → 08 Perencanaan Tahunan → 09 Semester → 10 Administrasi** beserta jalur kembali, gate dependency, pemilihan semester, scope penyimpanan, kegagalan, dan refresh.
2. Tes proyeksi Merdeka memakai `ATPItem.jp/semester` dan alokasi ATP lama sebagai sumber waktu. Fixture baru melewati layanan V21 untuk menghasilkan Unit → Meeting → Actual Schedule. Kasus negatif tetap memeriksa graph hilang, referensi menggantung, pertemuan duplikat, isolasi semester, kapasitas, dan tidak berubahnya input/storage. Seluruh 11 kasus K13 pada PROTA/Alokasi Waktu dipertahankan.
3. Tes Modul Ajar belum memasok graph pertemuan dan durasi kegiatan yang sekarang wajib. Assertion kesiapan cetak kini memakai `validateLearningPlanForModulAjar`, sedangkan build ID diuji sebagai metadata terinjeksi dengan fallback runtime yang eksplisit.
4. Tes ATP masih menuntut kolom/total JP pada Step 06, melarang TP berulang pada langkah berbeda, dan mencari blok sanitasi JP yang sudah digantikan whitelist keluaran. Tes endpoint kini menjalankan handler sebenarnya dengan provider fixture: Merdeka tanpa semester diterima, K13 tanpa semester ditolak, dan field JP/semester dari model tidak ikut keluar. Duplikasi dalam satu langkah tetap ditolak; dependency TP tetap wajib.
5. Smoke test memakai cara menjalankan npm yang gagal di Windows (`spawn EINVAL`), batas startup terlalu pendek, dan ekspektasi HTTP 503 pada endpoint TP yang sekarang memang menyediakan `pedagogical_engine`. Tes sekarang memeriksa fallback secara eksplisit, health JSON yang benar, startup berbatas waktu, serta build nyata; pembuatan HTML dummy dihapus.
6. Lint baseline memiliki 67 diagnostik tipe pada skrip tes. Fixture diperbarui mengikuti tipe saat ini: field wajib, impor tipe, status `SIAP`, dan identitas canonical. Tidak ada pengecualian tsconfig, penonaktifan tes, atau penambahan suppression.
7. Workflow semula berhenti pada kegagalan pertama. Empat kelompok matrix memakai `fail-fast: false`; pemeriksaan tipe dan build/production berjalan mandiri. Runner menjalankan semua anggota kelompok, menyimpan log/hasil, dan mengembalikan exit gagal bila ada kegagalan. Self-test membuktikan dua kegagalan di kedua sisi sebuah tes berhasil tetap terdeteksi. Tidak memakai `continue-on-error`.

## Batas bukti dan risiko tersisa

- Validasi lokal memakai Windows dan Node 24.20.0; workflow menetapkan Node 22 di Ubuntu. Run GitHub Actions remote belum menjadi bukti dari pekerjaan lokal ini.
- Workflow manual `calendar-grounding-diagnostic.yml` memerlukan secret dan layanan Gemini nyata; tidak dijalankan. Uji transport memakai fixture atau server tanpa kunci, bukan bukti live provider.
- Build memberi peringatan ukuran chunk besar. Beberapa fixture PDF memberi peringatan lebar tabel dari jsPDF. Pengujian memverifikasi keluaran, isi, ukuran halaman terkait, dan jalur kegagalan; tidak mengklaim audit visual seluruh dokumen.
